# Από το Workbench σε τεκμηριωμένη ερευνητική μελέτη

Έκδοση εργαλείου 1.2 — 4 Νοεμβρίου 2026. Το έγγραφο είναι σχέδιο εργασίας, όχι προεγγραφή, ανεξάρτητη αξιολόγηση ή έτοιμο paper.

## Ερευνητικό ερώτημα

Πότε και από ποιο μέλος μιας ομάδας πρέπει ένας ρομποτικός συντονιστής να ζητά επιβεβαίωση, ώστε να περιορίζει τις διακοπές και το κόστος τους, λαμβάνοντας υπόψη την αβεβαιότητα, την ταυτότητα του αντικειμένου, την ισχύ των πληροφοριών και τις προθεσμίες;

Η σημερινή εργασία είναι αφηρημένη μεταφορά εξοπλισμού με ένα Boolean προαπαιτούμενο ελέγχου για ένα καρότσι. Οι άνθρωποι απαντούν βάσει προγραμματισμένων σεναρίων. Δεν υλοποιείται πλήρες χειρουργικό πρωτόκολλο, ASR, φυσική πλοήγηση ή πραγματική ανθρώπινη ομάδα.

## Προτεινόμενες υποθέσεις

- **H1:** Η επιλεκτική επανεπιβεβαίωση μειώνει τις περιττές ερωτήσεις έναντι της υποχρεωτικής νέας επιβεβαίωσης. Η ορθότητα πρέπει να αναφέρεται παράλληλα, χωρίς συμπέρασμα μη κατωτερότητας από μικρά pilots.
- **H2:** Η συνεκτίμηση του κόστους αλλάζει την επιλογή πηγής και μπορεί να μειώνει το κόστος διακοπών έναντι cost_blind. Χρειάζεται έλεγχος τόσο κοινής καταγεγραμμένης πληροφορίας όσο και πραγματικών end-to-end εκτελέσεων.
- **H3:** Υβριδικός controller και απευθείας LLM μπορεί να διαφέρουν σε προτάσεις, ερωτήσεις, κόστος και λάθη. Η υπεροχή δεν προϋποτίθεται. Στα αρχικά pilots το LLM μπορεί να ισοφαρίζει τον υβριδικό controller.

Ο τρέχων selector είναι greedy ευρετική: βάρος × εκτίμηση γνώσης − κόστος − αναμονή. Δεν είναι μαθημένη πολιτική ή βέλτιστος value-of-information planner. Η ερευνητική συνεισφορά και η πρωτοτυπία χρειάζονται τεκμηρίωση έναντι της βιβλιογραφίας, όχι μόνο λειτουργικό UI.

## Τρεις χρήσεις που πρέπει να διατηρούνται διακριτές

| Χρήση | Τι εκτελείται | Τι επιτρέπεται να συμπεράνουμε |
|---|---|---|
| Διαδραστικό εργαστήριο | Browser simulator, δομημένα annotations, προγραμματισμένες απαντήσεις, δικές μας ενέργειες | Κατανόηση του προβλήματος και software checks. Δεν είναι LLM αξιολόγηση. |
| Live πείραμα | Νέες κλήσεις επιλεγμένων μοντέλων με κοινό prompt/σχήμα παρατήρησης και καταγραφή ανά γύρο | Περιγραφική απόδοση στις συγκεκριμένες συνθήκες, με κάλυψη, λάθη και όρια. |
| Controlled one-step diagnostic | Οι controllers δέχονται την ίδια καταγεγραμμένη δημόσια κατάσταση και την ίδια αποδεκτή εξαγωγή | Αν προτείνουν διαφορετική επόμενη ενέργεια. Δεν προκύπτουν υποθετικές πλήρεις εκβάσεις ή συνολικό κόστος. |

## Πειραματική διαδικασία

1. **Έλεγχος εργαλείου χωρίς κόστος μοντέλου.** Unit tests, offline fixtures και έλεγχος browser/Python parity. Τα tests ελέγχουν κώδικα και δεν μετρούν LLM accuracy.
2. **Πιλοτικός έλεγχος εξαγωγής.** Η αφετηρία D03/D05 εξετάζει ληγμένες και αντικρουόμενες αναφορές. Η D09/D10 εξετάζει επιλογή πηγής και γνώση άσχετου πεδίου. Πρόκειται για development περιπτώσεις.
3. **Έλεγχος κάθε model profile.** Exact model ID, μικρό αρχικό όριο και έλεγχος πρόσβασης/σχήματος από τον λογαριασμό του ερευνητή. Η παρουσία API key δεν πιστοποιεί έγκυρη πρόσβαση. Δεν αλλάζουμε σιωπηρά μοντέλο όταν αποτυγχάνει.
4. **Πάγωμα μελέτης.** Ίδια σενάρια, πολιτικές, επαναλήψεις, prompt και όρια output. Καταγράφονται πηγή σεναρίων, παραλλαγές κόστους, επιλεγμένα και πραγματικά επιστραφέντα model IDs, seed σειράς, κώδικας και μέγιστες αποφάσεις. Το σχέδιο δεν βαφτίζεται προεγγραφή μετά τη συλλογή δεδομένων.
5. **Live εκτέλεση.** Το αρχικό cap είναι όριο προσπαθειών, όχι ευρώ ή αυτόματη άδεια για ολόκληρο το θεωρητικό πλάνο. Η συνέχιση έχει νέο πρόσθετο cap. Άγνωστες/αποτυχημένες χρεώσιμες προσπάθειες δεν επαναλαμβάνονται αυτόματα.
6. **Αποτίμηση με πλήρεις παρονομαστές.** Αναφέρουμε ανατεθειμένες, ολοκληρωμένες, αποτυχημένες και μη ξεκινημένες προσπάθειες ανά συνθήκη. Οι τεχνικές αποτυχίες διακρίνονται από deadline/step limits. Διατηρούμε αρχικά και μετά-φίλτρο λάθη εξαγωγής.
7. **Controlled diagnostic.** Ελέγχουμε τις πολιτικές πάνω στα ίδια αποδεκτά στοιχεία ανά saved input για να ξεχωρίσουμε αλλαγή selector από διαφορετική stochastic εξαγωγή. Οι παρατηρήσεις προέρχονται από τις ήδη εκτελεσμένες διαδρομές, άρα δεν είναι ανεξάρτητα τυχαία δείγματα.
8. **Ανεξάρτητη αξιολόγηση.** Χρειάζονται νέα σενάρια, πραγματικός έλεγχος ομοιότητας/διαρροής, ανεξάρτητοι reviewers, καταγραφή συμφωνίας και προδιαγεγραμμένη ανάλυση. Οι σημαίες review του λογισμικού αποτελούν δηλώσεις και δεν υποκαθιστούν αυτή τη διαδικασία.

## Μετρικές και ανάλυση

- Ερωτήσεις, συνθετικό κόστος διακοπών, αναμονές και βήματα ανά προσπάθεια.
- Αναμενόμενη έκβαση βάσει του συνθετικού reference, με παρονομαστή το πλήρες πλάνο και χωριστή κάλυψη. Η άσκοπη κλιμάκωση δεν πρέπει να επιβραβεύεται μόνο επειδή μηδενίζει κόστος.
- Unsupported/unsafe προτάσεις πριν από το κοινό oracle gate. Η απουσία εκτελεσμένων λαθών μετά το gate δεν αποτελεί απόδειξη πραγματικής ασφάλειας.
- Αρχικά και μετά-φίλτρο λάθη εξαγωγής, απορριφθείσες αναφορές, έγκυροι scored γύροι και εξαιρέσεις. Γύροι διαλόγου και επαναλήψεις δεν είναι ανεξάρτητα σενάρια.
- Κλήσεις, tokens εισόδου/εξόδου, πραγματικό returned model ID και καθυστέρηση. Τα tokens μεταξύ διαφορετικών παρόχων δεν είναι άμεσα ισοδύναμα.
- Τυχαιοποιημένη σειρά blocks/συνθηκών με παγωμένο seed. Το seed αφορά τη σειρά και δεν εγγυάται deterministic LLM outputs.
- Περιγραφικές συγκρίσεις σε pilots. Για inferential ισχυρισμούς απαιτούνται εκ των προτέρων effect size, μονάδα δειγματοληψίας, ανάλυση διασποράς, sample-size justification και αντιμετώπιση πολλαπλών συγκρίσεων. Η απλή αύξηση επαναλήψεων δύο σεναρίων δεν λύνει το πρόβλημα ανεξαρτησίας.

## Τι παρέχει η 1.2 και τι απομένει

| Σκέλος | Κατάσταση |
|---|---|
| Μετάβαση από sandbox σε παγωμένη μελέτη | Υλοποιημένη. Μεταφέρονται αρχικό σενάριο και κόστη, όχι χειροκίνητες ενέργειες ή απαντήσεις. |
| Preview → δημιουργία → ξεχωριστή εκκίνηση | Υλοποιημένη, με έλεγχο stale source και stale plan. |
| Πολυμοντελικές συνθήκες, budgets, pause/resume | Διαθέσιμα. Οι πραγματικές νέες κλήσεις εκτελούνται στον λογαριασμό του ερευνητή. |
| Read-only audit κοινής εισόδου και research report | Υλοποιημένα, χωρίς νέες κλήσεις μοντέλου ή υποθετικές πλήρεις διαδρομές. |
| Πρωτοτυπία και ολοκληρωμένη βιβλιογραφική σύγκριση | Χρειάζεται τεκμηριωμένη ανασκόπηση με πρωτογενείς πηγές. |
| Ανεξάρτητο benchmark και συμφωνία reviewers | Εκκρεμούν. Τα υπάρχοντα candidate designs δεν επαρκούν ως απόδειξη ανεξαρτησίας. |
| Πραγματικά νέα live δεδομένα πολλών μοντέλων | Εκκρεμούν για τη νέα μελέτη. Mock calls και offline fixtures δεν προσμετρώνται ως live αποτελέσματα. |
| Κλινική, ανθρώπινη ή ενσώματη ρομποτική αξιολόγηση | Δεν έχει πραγματοποιηθεί. Θα χρειαστεί εφόσον απαιτείται από τους τελικούς ισχυρισμούς του paper. |

## Αρχεία που κρατάμε

Το ZIP πειράματος περιλαμβάνει session, dataset, κώδικα/prompt fingerprints, study design, episode/event CSV, decision audit JSON/CSV και research_report.md. Τα κλειδιά API δεν ανήκουν σε κανένα από αυτά. Η αναφορά τεκμηριώνει μία παγωμένη εκτέλεση· δεν συγχωνεύει αυτόματα διαφορετικές εκδόσεις ή διαφορετικά πρωτόκολλα.
